- **Enforcement model.** Server actions pass the session's numbers as `p_max_*` arguments. The SQL functions lock the workspace row, count and refuse. They hold no plan table: a missing limit raises `limits_required`, and otherwise they trust what the app sends.
  - create_monitor: `actions.ts:229-254` → `heartbeat_url_sealed.sql:82-113` (monitor_limit, heartbeat_limit, assertion_limit, interval_not_allowed with DNS ≥600 s and SSL =21,600 s, host_limit). Edits: `actions.ts:345-365` → `monitor_edit_closes_incident.sql:66-84`.
  - Stripe/Supabase: `actions.ts:307-315` → `service_monitors.sql:33-34` (monitor_limit, service_monitor_limit), with the interval checked only as a member of {60,180}/{300,600} (`:46,:60`). The plan interval for these types is therefore enforced only by the action.
  - Apps: `actions.ts:114` → `apps_limit_and_logo.sql:65-68`. Pages: `actions.ts:833` → `phase1_dashboard.sql:418-421`. Domain verification (`actions.ts:984-985` → `status_edge.sql:187-193`), demo clone (`clone/[slug]/actions.ts:44-46`) and the agent API (`agent-service.ts:145,197` → `agent_surface.sql:91-131`) pass the same limits.
  - Features: white_label and private_pages are refused in `save_status_page` (`phase1_dashboard.sql:462-470`) and coerced in `savePage` (`actions.ts:894-923`). Members-only is checked in `begin_private_page`/`save_status_page_access` (`status_edge.sql:123,142`). alert_rules is checked at `alerts/actions.ts:317` and `alert_channels.sql:71`. notify_teammates is checked at `alerts/actions.ts:122,139`, and the SQL raises `teammates_required`. subscribers is switched off (`launch.ts:93`).
  - Locations: the probe reads `probe_builder_workspaces` (`workspace_plan.sql:9-14`, `probe/store.ts:214`). `eligible()` keeps Free monitors off Builder-only probes (`probe/schedule.ts:46-48`). fra1 requires `PROBE_BUILDER_ONLY=true` (`probe/env.ts:18`).
  - API rate: `agent-auth.ts:130` → `agent_budget` (`agent_surface.sql:73-77`, which refuses any limit above 120). History is enforced only in the agent API (`agent-service.ts:52,276`). In the dashboard it is label text only.
  - MCP limits are display-only: the type can't be created (`heartbeat_url_sealed.sql:72-74`, `agent-service.ts:180`).
- **Plan-independent caps.** 100 active API tokens (`agent_surface.sql:66`), 3 pending custom domains (`status_edge_hosts.sql:20`), 50 components per page (`phase1_dashboard.sql:471`), pause ≤30 days (`ack_and_pause.sql:51`), interval_sec 60–86,400 (`phase1_dashboard.sql:76`). There are also the test, alert and Netlify budgets (`budgets.ts:12-35`, `netlify/edge-functions/*`).
- **Plan changes.** On upgrade, HTTP/TCP/Supabase monitors at 180 s move to 60 s. A downgrade only flips the stored plan: monitors aren't slowed, over-limit apps, pages and monitors stay, and private pages stay private (`workspace-plan.ts:8-20`, `apps_limit_and_logo.sql:63-64`, `status_edge.sql:141`).
